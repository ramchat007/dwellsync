# Authentication Architecture

## Overview

DwellSyncHub decouples user authentication from application profiles and multi-tenant authorization:
- **Authentication Provider**: Managed strictly by Supabase Auth (`auth.users`).
- **Application Profile**: Stored in `public.profiles` keyed by `id UUID REFERENCES auth.users(id)`.
- **Session Lifecycle**: Handled using `@supabase/ssr` with secure HTTP-only cookies and Next.js App Router middleware.

## Database Model Separation

```
auth.users (Managed by Supabase Auth)
  │
  ▼ [Trigger: on_auth_user_created]
public.profiles
  ├── public.platform_admins (Platform-level Super Admin role)
  ├── public.society_memberships (Tenant-level roles & unit assignments)
  └── public.impersonation_sessions (Server-controlled audit sessions)
```

## Credential Security Rules

1. **Zero Password Storage in Application DB**: Passwords are never stored in application tables or custom fields.
2. **UUID Primary Keys**: User IDs are always UUIDs generated by Supabase Auth. Email is not used as the primary foreign key.
3. **Automatic Profile Synchronization**: A PostgreSQL `SECURITY DEFINER` trigger `handle_new_user()` automatically synchronizes profile rows upon user registration.

## Server-Side Session Handling

Session tokens are refreshed transparently in `src/middleware.ts` using `@supabase/ssr`. Route protection verifies the user's authenticated session before rendering protected layouts.
